# Работа с ИИ-агентом (Zed)

> Короткие always-on правила — [`../AGENTS.md`](../AGENTS.md); переносимый стандарт —
> [`../PROJECT-BLUEPRINT.md`](../PROJECT-BLUEPRINT.md); EN-скилы — [`../.agents/skills/`](../.agents/skills/README.md).
> Здесь — практика: как ставить задачу, что проверять и где границы.

## Принципы

1. **Маленькими шагами.** План → минимальная правка под задачу → проверка → следующий шаг.
   Крупное изменение — сначала планом, потом код.
2. **Сначала документация.** Перед задачей агент читает нужные `docs/*.md` и подходящий скил
   из `.agents/skills/`. Скилы — EN-«рецепт + указатели»; источник правды — `docs/` (RU).
3. **Не выходить за scope.** Правки — только под задачу; не рефакторить «попутно», не менять
   файлы, которых задача не касается.
4. **Экономия контекста (токенов).** Точечный просмотр (`grep`/`find_path`), чтение только нужных
   файлов, не перечитывать уже прочитанное. Не тащить в задачу лишние файлы и «на всякий случай» код.
5. **Проверка офлайн — часть задачи.** См. ниже; что не проверялось — сказать прямо.
6. **Git — человек.** Агент не делает `commit`/`branch`/`push`/`tag`; коммитит человек после ревью.

## Проверки (офлайн)

```sh
# Go (main.go встраивает frontend/dist — для проверки нужна заглушка):
mkdir -p frontend/dist && touch frontend/dist/index.html
go test ./internal/... && go vet ./internal/...
golangci-lint run

# Фронтенд:
cd frontend && npm run typecheck && npm run lint && npm test
```

То же через Taskfile: `task lint`, `task typecheck`, `task test`, `task check`.
Тяжёлые сборки (`wails3 build`, `wails3 package`) — только по явной просьбе.

## Скилы

Скилы живут в `.agents/skills/` (EN). Zed подгружает их по описанию; можно указать явно:

```
Прочитай .agents/skills/proxy-tester/SKILL.md и реализуй тест latency.
```

Скил не вводит фактов, которых нет в `docs`/коде; при изменении факта обновляй и скил.

## Шаблон промпта для старта задачи

```
Ты работаешь над проектом Proxy Pool Manager (Wails v3 + Go + React + TS).
Работаем по AGENTS.md и PROJECT-BLUEPRINT.md.

Перед началом прочитай:
- docs/REQUIREMENTS.md, docs/ARCHITECTURE.md, docs/DATA_MODEL.md (по необходимости)
- .agents/skills/<нужный_скил>/SKILL.md

Задача: Milestone <N> — <название>.

Ограничения:
- Только в рамках задачи; не менять файлы вне scope.
- Не добавлять системные вызовы, системный прокси, тяжёлые зависимости.

Результат:
- Код, проходящий офлайн-проверки (см. AGENTS.md).
- Короткий отчёт: что изменено, какие файлы, что и как проверено.
```

## Шаблон промпта для продолжения

```
Продолжаем Milestone <N>. Предыдущие шаги: <список>.
Следующий шаг: <подзадача>.
Убедись, что предыдущие шаги не сломаны; прогони проверки.
```

## Шаблон промпта для ревью

```
Проведи ревью кода в рамках Milestone <N>.
Проверь: соответствие docs/ARCHITECTURE.md и docs/CONVENTIONS.md, отсутствие утечек
горутин/подписок, корректность работы с SQLite (транзакции, prepared statements),
отсутствие вызовов вне scope, покрытие тестами критичных путей.
Выведи список замечаний и предложений.
```

## Откат изменений

Если агент сломал предыдущий шаг — откат делает **человек**:

```bash
git log --oneline               # найти последний рабочий коммит
git reset --hard <commit-hash>  # откатить
```
