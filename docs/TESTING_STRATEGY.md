# Стратегия тестирования

## Тестирование прокси

### Latency

**Метод:** TCP-connect к `host:port` через `net.DialTimeout`.

- Таймаут по умолчанию: 5 секунд (настраивается).
- Замер: время от начала вызова до успешного `connect` или ошибки.
- Только успешный connect даёт `is_working = true`.
- При ошибке `latency_ms = null`, `is_working = false`.

**Альтернатива (для HTTP/SOCKS):** лёгкий HTTP-запрос к
`http://httpbin.org/ip` или `https://api.ipify.org?format=json` через прокси.
Используется, если TCP-connect успешен, но нужно подтвердить, что прокси
реально пропускает трафик. Применяется реже, чтобы не перегружать сеть.

### Скорость (download)

**Метод:** скачивание файла через прокси с замером времени.

- URL по умолчанию: `https://speed.cloudflare.com/__down?bytes=1000000` (1 МБ).
- Размер настраивается: 100 КБ – 10 МБ.
- Замер: `bytes / elapsed_seconds`, в Mbps.
- Таймаут: 30 секунд.
- Тест скорости запускается **только для прокси, прошедших latency-тест**.

### Конкурентность

- Латентность: семафор на `test_concurrency` (по умолчанию 50).
- Скорость: семафор на 10.
- Батчи: по 50 прокси, между батчами пауза 1 сек (для снижения нагрузки на DNS).

### Отмена

- `context.WithCancel` создаётся на каждый массовый тест.
- `context.CancelFunc` сохраняется в TesterService.
- При отмене все активные горутины завершают работу, событие
  `test:completed` отправляется с флагом `cancelled: true`.

### Повторный тест

- Выбранные прокси — по кнопке или хоткею.
- Все нерабочие — по отдельной кнопке.
- Все в пуле — с подтверждением (может быть долго).

## Тестирование приложения

### Go (backend)

- **Unit-тесты:**
  - `parser_test.go` — парсинг `ip:port`, `protocol://ip:port`, JSON.
  - `storage_test.go` — CRUD, дедупликация, фильтрация, экспорт.
  - `tester_test.go` — тесты с мок-серверами (`httptest`).
- **Инструменты:** стандартный `testing`, `github.com/stretchr/testify`.
- **Команда:** `go test ./...`

### Frontend

- **Unit-тесты:**
  - Компоненты таблицы: рендер, сортировка, выбор.
  - Утилиты: форматирование latency, копирование в буфер.
- **Инструменты:** `vitest`, `@testing-library/react`, `@testing-library/jest-dom`.
- **Команда:** `npm run test` (в `frontend/`).

### Интеграционные

- **Сценарии:**
  1. Добавить источник URL → проверить, что прокси попали в БД.
  2. Запустить тест latency → проверить обновление статуса.
  3. Отфильтровать только рабочие → проверить корректность.
  4. Копировать выбранные → проверить буфер обмена.
- **Инструменты:** Playwright + Wails headless (опционально, на поздних этапах).

### Ручное тестирование

- **Список чек-листов для релиза:**
  - [ ] Сборка `wails3 build` проходит без ошибок.
  - [ ] Приложение запускается на чистой системе (Linux GNOME и KDE).
  - [ ] Тёмная и светлая темы корректно переключаются.
  - [ ] Массовый тест 100 прокси завершается < 30 сек.
  - [ ] Отмена теста не оставляет висящих горутин.
  - [ ] Копирование в буфер работает в GNOME и KDE.
  - [ ] Экспорт в TXT/CSV/JSON корректен.
  - [ ] SQLite-файл создаётся в правильной директории.

## Метрики качества

- Покрытие Go-кода тестами: ≥ 60% на момент Milestone 4.
- Покрытие Frontend: ≥ 40% на момент Milestone 4.
- Отсутствие `go vet` и `eslint` предупреждений.
